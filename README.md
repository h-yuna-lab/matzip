# 🍽️ 천안맛ZIP

> “천안 내 상황에 딱 맞는 진짜 맛집을 찾다”

리뷰의 방문 상황·테마 데이터를 활용해 사용자의 방문 목적에 맞는 천안 맛집 선택을 돕는 웹 서비스입니다.

**5인 팀 프로젝트를 홍유나의 개인 포트폴리오로 정리한 통합 저장소**입니다. 사용자 React 화면과 Spring Boot·Thymeleaf 서버를 한곳에 모았으며, 개인 담당은 **리뷰 CRUD 공동 구현, 관리자 맛집 수정·삭제, 기능 테스트와 발표자료 제작**입니다.

- 맛집 목록·상세 조회와 카테고리·상황·테마 기반 탐색
- 별점·재방문 의사·상황 태그·이미지를 포함한 리뷰 작성·수정·삭제

- 사용자·관리자 권한 구분과 Thymeleaf 관리자 맛집 관리

## 실행 방법

Node.js·Java 실행 환경·Oracle DB를 준비하고, [백엔드](backend/README.md)에서 DB·테이블·비공개 설정 파일을 먼저 확인합니다. 프론트 `.env`는 `frontend` 폴더에 준비합니다.

통합 저장소 루트에서 각각 별도 터미널로 실행합니다.

```powershell
# 터미널 1 · 백엔드
cd backend
.\gradlew.bat bootRun
```

```powershell
# 터미널 2 · 프론트엔드
cd frontend
npm install
npm run dev
```

서버는 `http://localhost:8111`, 사용자 화면은 Vite가 터미널에 표시한 주소입니다.

## 프로젝트 회고

### 리뷰 수정·삭제와 맛집 통계를 함께 갱신

리뷰 CRUD를 공동 구현하면서 제가 추가한 수정·삭제 기능은 리뷰 본문만 바꾸는 것으로 끝나지 않았습니다. 리뷰에는 별점, 이미지, 태그가 연결되어 있고 맛집 목록에는 평균 별점과 리뷰 수가 표시됩니다. 기존 통계 갱신 쿼리는 리뷰 수만 변경하고 있어, 리뷰의 별점을 수정하거나 리뷰를 삭제해도 맛집에 저장된 평균 별점이 실제 리뷰와 달라질 수 있었습니다.

수정·삭제 전에 작성자 ID와 현재 회원 ID를 비교해 본인 리뷰만 변경할 수 있도록 처리했습니다. 리뷰 수정에서는 본문과 별점을 갱신한 뒤 기존 이미지·태그를 제거하고 전달받은 항목을 다시 저장했습니다. 삭제에서는 리뷰와 연결 데이터를 함께 제거하고, 두 작업 모두 이후에 리뷰 수와 평균 별점을 다시 계산하도록 변경했습니다. 리뷰가 하나도 남지 않은 경우에는 평균을 0으로 처리했으며, 관련 변경이 하나의 트랜잭션 안에서 실행되도록 구성했습니다.

이 과정에서 기능의 완료 기준을 “수정 요청이 성공했다”로 잡으면 부족하다는 점을 배웠습니다. 변경된 리뷰뿐 아니라 연결 데이터와 목록의 집계 값까지 일치해야 사용자가 보는 결과도 올바르게 유지됩니다.

관련 변경: [리뷰 수정·삭제, 작성자 확인 및 통계 갱신](https://github.com/SangHyunPark1213/human_mini_project2_backend/commit/3e79bc5c28533dda036ab98db88260d27cf88840)

### 관리자 이미지 수정의 업로드 흐름 연결

관리자 맛집 수정 화면은 기존 수정 요청에 대표 이미지 URL이 포함되지 않아 이미지를 바꾸는 흐름이 완성되지 않은 상태였습니다. 관리자 목록 화면에 Firebase 설정도 전달되지 않았기 때문에, 파일 선택부터 업로드와 수정 API 호출까지 연결할 필요가 있었습니다.

컨트롤러에서 화면에 Firebase 설정을 전달하고 Storage를 초기화하도록 수정했습니다. 기존 이미지는 미리보기와 URL로 보관하고, 새 파일을 선택했을 때만 업로드한 뒤 다운로드 URL을 받아 맛집 수정 요청에 포함했습니다. 파일을 새로 선택하지 않으면 기존 URL을 유지하도록 했습니다. 업로드와 수정 요청이 진행되는 동안 버튼을 비활성화하고, 성공 시 목록을 다시 불러오며 실패 시 응답 상태를 안내하도록 보완했습니다.

파일 선택 화면이 보이는 것과 실제 이미지가 저장되는 것은 별개의 작업이라는 점을 경험했습니다. 외부 저장소 업로드와 서버의 정보 수정이 순서대로 이어져야 하므로, 정상 흐름뿐 아니라 어느 단계에서 실패했는지도 구분해야 한다고 느꼈습니다.

관련 변경: [Firebase 업로드·대표 이미지 URL·미리보기 연결](https://github.com/SangHyunPark1213/human_mini_project2_backend/commit/124e0eacf9dc29d512cd00a4d11b28be6f45d006)

### 앞으로 보완할 부분

리뷰 수정 후 평균 별점이 바뀌는 경우, 마지막 리뷰 삭제, 다른 회원의 수정 요청, 이미지 유지·교체를 테스트 시나리오로 정리하고 싶습니다. 특히 이미지 업로드는 성공했지만 맛집 정보 저장에 실패하면 사용하지 않는 파일이 남을 수 있으므로, 실패 시 파일 정리와 재시도 기준도 보완해야 합니다. 공동 구현한 API의 권한과 요청·응답 형식을 먼저 합의하고, 사용자 화면까지 변경 결과가 반영되는지 확인하는 습관을 들이겠습니다.
